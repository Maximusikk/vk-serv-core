# Референс-бот продавца VKTurn (G8)

Пример Telegram-бота (Python 3.10+, aiogram 3) поверх Admin API (`docs/API.md`).
Оплаты в нём **нет**: это каркас, который продавец дорабатывает под свой платёжный сервис.

## Команды

| Команда | Кто | Что делает |
|---|---|---|
| `/buy <order_id> [дней] [ГБ]` | после оплаты | выдаёт ключ и ссылку; `ГБ=0` — безлимит. Повтор с тем же `order_id` вернёт тот же ключ (идемпотентно) |
| `/status [ключ]` | владелец ключа | статус, остаток дней, трафик, привязка к устройству |
| `/traffic [ключ]` | владелец ключа | использовано / лимит |
| `/extend [ключ] [дней]` | после оплаты | продлевает; погашенный ключ оживает сам |
| `/addtraffic [ключ] <ГБ>` | после оплаты | докупка трафика (у безлимитного ключа — ошибка 400) |
| `/unbind [ключ] yes` | владелец ключа | смена телефона; не чаще раза в 7 дней |

Если ключ не указан, берётся последний ключ пользователя.

## Как считается срок

Срок идёт **с момента первой активации** в приложении, а не с момента выдачи ключа
(`"start": "on_activation"`, решение C5). Пока покупатель не запустил приложение, `/status`
показывает «не активирован, срок N дн. начнётся с первой активации». `/extend` до активации
добавляет дни к сроку и отсчёт не запускает.

## Запуск

```bash
cd examples/seller_bot
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

export BOT_TOKEN=...                 # токен от @BotFather
export VKTURN_API_URL=http://203.0.113.10:7000
export VKTURN_ADMIN_TOKEN=...        # из /opt/vkturn/config.txt
export ADMIN_IDS=123456789           # Telegram-id продавца (через запятую)
python bot.py
```

| Переменная | Обязательна | По умолчанию | Смысл |
|---|---|---|---|
| `BOT_TOKEN` | да | | токен Telegram-бота |
| `VKTURN_API_URL` | да | | адрес API без `/v1` |
| `VKTURN_ADMIN_TOKEN` | да | | admin-токен сервера |
| `ADMIN_IDS` | нет | пусто | кто может покупать без проверки оплаты |
| `DEFAULT_DAYS` | нет | `30` | срок по умолчанию |
| `DB_PATH` | нет | `seller_bot.db` | локальная база «заказ → пользователь → ключ» |
| `OPEN_PURCHASES` | нет | выкл. | `1` — разрешить покупки всем. **Только для тестов** |

Для постоянной работы запустите под systemd с `EnvironmentFile=` (права `600`), токены не
кладите в репозиторий и не пишите в логи.

## Куда подключить оплату

В `bot.py` функция `may_purchase(uid)` решает, можно ли выдавать и продлевать. По умолчанию
это только `ADMIN_IDS`. Замените её проверкой вашего платёжного сервиса (вебхук или статус
заказа) и передавайте в `/buy` настоящий `order_id` из платёжки: именно он делает выдачу
идемпотентной, так что повторный вебхук не создаст второй ключ.

## Важно

- Если на сервере включён `-admin-allow`, добавьте в него IP машины с ботом.
- Бот хранит связь «заказ → пользователь → ключ» у себя. Потеряете `seller_bot.db` — `/buy`
  по уже оплаченным заказам отдаст ключ только админу (чужим пользователям отказывает).
  Делайте бэкап файла.
- Запросы к API идут по HTTP (без TLS, решение D0): admin-токен виден в сети, поэтому
  запускайте бота на доверенном хосте и по возможности включите `-admin-allow`.
