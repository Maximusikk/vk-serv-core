# VKTurn — руководство продавца

Здесь описано, как поставить сервер, подключить бота и что делать, когда что-то сломалось.
Все команды выполняются на сервере под root. Подробное описание запросов к API — в `docs/API.md`.

## 1. Что нужно

- VPS с Ubuntu 20.04+ или Debian 10+, процессор x86_64 или arm64. Нужен root-доступ по SSH.
- Белый IP-адрес. Домен не нужен: API работает по HTTPS со своим самоподписанным
  сертификатом, который клиенты проверяют по пину (см. раздел 11).
- Ссылка на звонок VK без пароля: ВКонтакте → Звонки → Создать звонок → Конференция.
  Ссылка выглядит как `https://vk.com/call/join/XXXX`.

## 2. Установка

```bash
curl -s https://raw.githubusercontent.com/Maximusikk/vk-serv-core/main/install.sh | sudo bash
```

Скрипт спросит ссылку VK. Если терминала нет (например, запуск из скрипта), передайте её заранее:

```bash
VK_LINK='https://vk.com/call/join/XXXX' sudo -E bash install.sh
```

Если скрипт не смог определить IP, добавьте `SERVER_IP=1.2.3.4`.

В конце скрипт выведет:

- ссылку `vkturn://v1/...` для подключения без ключа (для себя, для проверки);
- строку `VKTURN_ADMIN_TOKEN=...` — это токен администратора. Сохраните его;
- строку `VKTURN_ADMIN_PIN=...` — пин TLS-сертификата API (64 hex-символа). Это не секрет,
  но он нужен боту и админке, чтобы убедиться, что они говорят именно с вашим сервером;
- пример `curl --pinnedpubkey sha256//...` для создания ключа.

Повторный запуск на уже установленном сервере скрипт откажется выполнять. Чтобы всё же
переустановить: `FORCE_REINSTALL=1`. Перед этим скрипт сделает копию в `/opt/vkturn/backup-<дата>/`.
Но лучше использовать обновление (раздел 6).

### Что откроется в файрволе

| Порт | Зачем |
|---|---|
| 56000/udp | основное подключение |
| 56001–57000/udp | личные порты ключей (до 1000 ключей одновременно) |
| 7000/tcp | API (только HTTPS) |
| порт SSH | скрипт находит его сам и не закрывает |

Если у хостинга свой файрвол в панели, эти порты надо открыть и там.

### Что где лежит

| Путь | Что это |
|---|---|
| `/opt/vkturn/config.txt` | настройки и секреты (права 600). Не публикуйте |
| `/opt/vkturn/api.env` | токены API (права 600). Здесь же задаются переменные API |
| `/opt/vkturn/api.db` | база ключей |
| `/opt/vkturn/tls/` | сертификат API `api.crt` и его закрытый ключ `api.key` (права 600, секрет). Каталог 700 |
| `/opt/vkturn/users/` | конфиги личных портов |
| `/var/log/vkturn/` | логи (хранятся 7 дней) |

Службы: `vkturn-api`, `vkturn-server`, `vkturn-hy2` и по одной `vkserv@<порт>` на каждый активный ключ.

Посмотреть состояние: `systemctl status vkturn-api`. Логи: `journalctl -u vkturn-api -n 50`.

## 3. Подключить бота

Бот ходит в API по HTTPS с токеном администратора. Нужны три значения.

**Токен.** Его вывел установщик. Если потеряли: `grep ADMIN_TOKEN /opt/vkturn/config.txt`.

**Пин.** Строка `VKTURN_ADMIN_PIN=` из вывода установщика. Если потеряли:
`grep TLS_PIN /opt/vkturn/config.txt`, либо пересчитать из сертификата:

```bash
# hex (для бота и приложений)
openssl x509 -in /opt/vkturn/tls/api.crt -pubkey -noout \
  | openssl pkey -pubin -outform DER | sha256sum | cut -d' ' -f1
# base64 (для curl --pinnedpubkey)
openssl x509 -in /opt/vkturn/tls/api.crt -pubkey -noout \
  | openssl pkey -pubin -outform DER | openssl dgst -sha256 -binary | openssl base64 -A
```

Пин копируйте из SSH-сессии, а не «спрашивайте» у сервера по сети: смысл пина в том,
чтобы проверить сеть, а не доверять ей.

**Публичный адрес для ссылок.** Установщик сам записывает `PUBLIC_URL=<IP сервера>:7000` в
`/opt/vkturn/api.env`, а `upgrade.sh` добавляет эту строку на уже установленных серверах.
Этот адрес попадает в поле `link` ответа `create`. Проверьте, что он на месте:

```bash
grep PUBLIC_URL /opt/vkturn/api.env
```

Если строки нет (сервер поставлен давно и ни разу не обновлялся), без неё `create` вернёт ссылку
с адресом `127.0.0.1:7000`, и она не заработает. Запустите `upgrade.sh` (раздел 6) или добавьте строку
вручную, подставив свой IP, и выполните `systemctl restart vkturn-api`:

```
PUBLIC_URL=203.0.113.10:7000
```

Проверка с любого компьютера (`PIN_B64` — base64-пин из команды выше):

```bash
curl -s --pinnedpubkey "sha256//$PIN_B64" -k https://203.0.113.10:7000/health
```

Должно прийти `{"ok":true}`. Если не пришло, проверьте, что порт 7000 открыт (раздел 2).
`curl: (90) ... does not match pinned public key` — пин не тот (или вы подключились не к своему
серверу). `-k` нужен только вместе с `--pinnedpubkey` (сертификат самоподписанный); без пина
`-k` не используйте нигде, кроме `https://127.0.0.1:7000` на самом сервере.

Дальше два пути:

- свой бот: порядок запросов — в конце `docs/API.md`;
- готовый пример на Python (aiogram): папка `examples/seller_bot/`, инструкция в её `README.md`.
  Оплаты в примере нет, её подключаете вы. Боту нужны `VKTURN_API_URL=https://IP:7000`,
  `VKTURN_ADMIN_TOKEN` и `VKTURN_ADMIN_PIN` (без пина бот не запустится). Свой бот обязан
  сверять пин до отправки токена — не отключайте проверку сертификата (`verify=False`) без пина.

Выдать первый ключ вручную:

```bash
curl -s --pinnedpubkey "sha256//$PIN_B64" -k \
  -X POST https://203.0.113.10:7000/v1/admin/keys/create \
  -H "X-Admin-Token: ТОКЕН" \
  -d '{"expires_days":30,"bytes_limit":53687091200,"external_id":"test-1"}'
```

В ответе поле `link` — ссылка для покупателя вида
`vkturn://key/203.0.113.10:7000/<ключ>?pin=<hex>`. Он вставляет её в приложение целиком:
по параметру `pin` приложение проверяет сервер до отправки ключа.

**Когда начинается срок.** С первой активации в приложении, а не с момента выдачи ключа.
Пока покупатель не запустил приложение, дни не тратятся.

## 4. Обновить ссылку VK

Нужно, когда звонок VK удалили или ссылка перестала работать. Проверить можно так:

```bash
curl -s --pinnedpubkey "sha256//$PIN_B64" -k https://203.0.113.10:7000/v1/admin/health -H "X-Admin-Token: ТОКЕН"
```

Если `vk_link_ok` равно `false`, ссылка не проходит проверку.

Создайте новый звонок (без пароля) и поменяйте ссылку одним из способов.

Через API:

```bash
curl -s --pinnedpubkey "sha256//$PIN_B64" -k -X PUT https://203.0.113.10:7000/v1/admin/vk \
  -H "X-Admin-Token: ТОКЕН" \
  -d '{"vk_link":"https://vk.com/call/join/НОВАЯ"}'
```

Или на сервере: `sudo bash /opt/vkturn/update-vk.sh` (спросит ссылку).

Новая ссылка используется при всех новых активациях. Уже выданные конфиги она не меняет.
Как это увидят пользователи, зависит от версии приложения. Автоматическая повторная
активация в приложении сейчас в разработке (задача H2): проверьте на вашей сборке.

## 5. Лимиты сервера

- Диапазон портов даёт максимум 1000 ключей с запущенным подключением одновременно.
- Чтобы ограничить число раньше, задайте в `api.env` `MAX_ACTIVE=N` и перезапустите `vkturn-api`.
  Когда лимит достигнут, новые активации получают отказ 503 «Сервер заполнен».
  Нагрузку одного ключа на процессор и память ещё не замеряли, подберите `N` по своему серверу.
- Посмотреть, сколько занято: `GET /v1/admin/stats` (поля `capacity`, `active_units`, `free_ports`).
- Свободное место на диске: `disk_free_mb` в `GET /v1/admin/health`.
- Уведомления (G5): сервер сам сообщит, если VK-ссылка умерла, диск < 500 МБ
  или порты заняты на ≥ 90%. Добавьте в `/opt/vkturn/api.env` строку
  `NOTIFY_URL=<webhook>` и перезапустите `vkturn-api` (`systemctl restart vkturn-api`).
  Webhook — любой URL, принимающий POST с JSON, например Bot API Telegram:
  `https://api.telegram.org/bot<ТОКЕН>/sendMessage?chat_id=<CHAT_ID>` — но у Telegram
  тело должно быть form-encoded, поэтому лучше ставить у себя простой мостик
  (пример — `examples/seller_bot`) или использовать свой HTTP-бот.
  JSON: `{"type":"vk_link_dead|disk_low|ports_low","message":"…","ts":…,"api_version":"…"}`.
  Повтор одного и того же события — не чаще раза в 6 часов.

## 6. Обновить сервер

```bash
sudo bash upgrade.sh
```

Файл `upgrade.sh` берётся из репозитория. Если по ссылке из репозитория 404, возьмите файл у владельца.
Другая версия: `VKSERV_VERSION=v1.0.3 sudo -E bash upgrade.sh`.

Что делает скрипт:

1. Скачивает новые программы и сверяет контрольные суммы.
2. Копирует базу в `/opt/vkturn/backup-upgrade/api.db.<дата>` (хранятся 5 последних).
3. Заменяет программы и перезапускает службы.
4. Если служба не запустилась или API не отвечает, откатывает на прежнюю версию.
5. После успешного рестарта читает TLS-пин, пишет `TLS_PIN=` в `config.txt` и печатает его.

**Переход на версию с HTTPS API.** После такого обновления API больше не отвечает по
`http://`. Старые приложения (и админка, и пользовательское) и старый бот перестанут работать с API.
Порядок: сначала раздать обновлённые приложения, затем `upgrade.sh`, затем прописать пин в
админке и боте (`VKTURN_API_URL=https://...`, `VKTURN_ADMIN_PIN`) и перевыдать покупателям
ссылки с `?pin=` (см. `docs/API.md`, «Что сломается у старых клиентов»).

Ключи, пароли и ссылка VK при обновлении сохраняются. Вернуть базу вручную:

```bash
systemctl stop vkturn-api
cp /opt/vkturn/backup-upgrade/api.db.<дата> /opt/vkturn/api.db
systemctl start vkturn-api
```

## 7. Бэкап

Положите `backup.sh` на сервер и запустите:

```bash
sudo bash backup.sh --install
```

Скрипт сделает бэкап сразу и поставит ежедневный запуск в 04:30. Архивы лежат в
`/opt/vkturn/backups/`, хранятся 7 последних. В архиве: база, `config.txt`, папка `users/` и `tls/`
(сертификат и закрытый ключ API — благодаря им после переезда пин не меняется).
Разовый бэкап без таймера: `sudo bash backup.sh`.

Архив содержит секреты (токены, пароли), права на него 600. Не отправляйте его никому.

**Копируйте архивы не на этот же сервер.** Если VPS пропадёт, бэкап пропадёт вместе с ним.
Например, раз в день забирайте свежий архив по `scp` на другой компьютер.

Основные секреты и пароли хранятся в `config.txt`, он лежит в архиве. Файлы `api.env`, `hy2.yaml`
и службу `vkturn-server` при переезде скрипт `restore.sh` приводит в соответствие с `config.txt`
сам, отдельно их копировать не нужно (раздел 8).

## 8. Переезд на другой сервер

Так задумано скриптами:

1. На старом сервере: `sudo bash backup.sh`.
2. Скопировать архив на новый: `scp /opt/vkturn/backups/vkturn-*.tar.gz root@НОВЫЙ:/root/`.
3. На новом: выполнить установку (раздел 2). Установщик создаст свои пароли и токен,
   они будут заменены на следующем шаге.
4. На новом: `sudo bash restore.sh /root/vkturn-*.tar.gz`.
   Скрипт заменит базу, `config.txt` и `users/`. Затем он подставит пароли и токены из `config.txt`
   в `hy2.yaml`, службу `vkturn-server` и `api.env`. Поэтому токен администратора остаётся прежним:
   бот и приложение менять не нужно. Если IP изменился, скрипт спросит, заменить ли `SERVER_IP`
   на адрес нового сервера.
5. Адрес в ссылках покупателей остаётся старым. Каждому нужна новая ссылка: либо снять
   привязку (`unbind`) и выдать ссылку с адресом нового сервера, либо разослать ссылки заново.
   `PUBLIC_URL` на новом сервере установщик задаёт сам, уже с новым IP.
6. Проверьте: `curl -s --pinnedpubkey "sha256//$PIN_B64" -k https://НОВЫЙ_IP:7000/v1/admin/health -H "X-Admin-Token: ТОКЕН"`
   с прежним токеном и подключение с телефона по одному из ключей.
   **Пин после переезда.** Если в архиве есть папка `tls/` и `restore.sh` её вернул, пин прежний;
   иначе на новом сервере другой пин (`grep TLS_PIN /opt/vkturn/config.txt`) — обновите его в боте и
   админке. В любом случае после смены IP выполните `rotate-cert.sh` (без `--new-key`), чтобы новый
   IP попал в сертификат; пин при этом не меняется.

**Проверка.** Эту схему проверили по коду скриптов, но ни разу не на живом сервере.
Сделайте пробный переезд на тестовом VPS до того, как он понадобится по-настоящему.

## 9. Если IP сервера заблокировали

Сначала убедитесь, что дело в блокировке, а не в службах:

```bash
systemctl status vkturn-api vkturn-server vkturn-hy2
curl -s -k https://127.0.0.1:7000/health      # на самом сервере (loopback, -k допустим)
curl -s --pinnedpubkey "sha256//$PIN_B64" -k https://IP_СЕРВЕРА:7000/health   # с другого компьютера
```

Если на сервере всё работает, а снаружи не отвечает, проверьте порты в панели хостинга (раздел 2).
Если порты открыты, а снаружи по-прежнему недоступно, IP, скорее всего, закрыт. Единственный
способ вернуть работу, который есть в скриптах: поднять сервер на другом IP и сделать переезд
(раздел 8). Покупателям понадобятся новые ссылки.

## 10. Вопросы покупателей

Приложение показывает причину отказа. Что делать:

| Что пишет покупатель | Причина | Что сделать |
|---|---|---|
| «Ключ не найден» | ошибка в ключе, или ключ удалён | проверить ключ: `GET /v1/admin/keys/<ключ>` |
| «Срок действия ключа истёк» | вышел срок | продлить: `PATCH` с `expires_days` |
| «Лимит трафика исчерпан» | кончились ГБ | докупить: `add_traffic` |
| «Ключ уже активирован на другом устройстве» | сменил телефон или вставил ключ на втором | `unbind`, затем вставить ту же ссылку на нужном устройстве |
| «Ключ отозван» | вы отозвали ключ | вернуть нельзя, выдайте новый |
| «Сервер заполнен» | достигнут `MAX_ACTIVE` | увеличить `MAX_ACTIVE` или подождать и повторить |
| «Обнови приложение» | старая версия приложения | установить новую |
| «VK ссылка не настроена» | в `config.txt` нет ссылки | задать ссылку (раздел 4) |
| Много запросов подряд, ответ 429 | больше 10 активаций в минуту с одного IP | подождать минуту |

`unbind` можно делать раз в 7 дней на один ключ. Раньше срока сервер отвечает 429.

После продления или докупки погашенный ключ оживает сам: сервер выдаёт новый порт,
пользователю вводить ключ заново не нужно.

Продлевать бессрочный ключ нельзя: запрос `expires_days` превратит его в ключ со сроком.
Проверяйте `days_left` (у бессрочного `-1`).

## 11. Безопасность

- **TLS и пин.** API слушает только HTTPS на `:7000`. Сертификат самоподписанный (ECDSA P-256,
  10 лет), API создаёт его сам в `/opt/vkturn/tls/`. Клиенты не доверяют ему «по умолчанию», а
  сверяют пин — SHA-256 открытого ключа (SPKI), 64 hex-символа — и только потом отправляют
  токен или ключ. Админка берёт пин из SSH-вывода установщика (`VKTURN_ADMIN_PIN=`), покупатель —
  из ссылки (`?pin=`), бот — из `VKTURN_ADMIN_PIN`. Пин не секрет, а вот `tls/api.key` — секрет.
  Подробно: `docs/API.md`, раздел «TLS и пин».
- **Лимитер админки.** 10 неверных токенов за минуту с одного IP — и дальше до конца минуты
  `/admin/*` с этого IP отвечает 429 даже на верный токен. Успешные запросы лимит не тратят.
- **Ротация сертификата:** `sudo bash rotate-cert.sh` — новый сертификат с тем же ключом,
  пин не меняется. `sudo bash rotate-cert.sh --new-key` — если `api.key` мог утечь: новый пин,
  после этого обновите пин в боте и админке и перевыдайте ссылки всем покупателям.
  Скрипт делает бэкап в `/opt/vkturn/tls-backup/`, проверяет API и при сбое откатывается.
- Можно разрешить `/admin/*` только с определённых IP. В `api.env` добавьте
  `ADMIN_ALLOW=203.0.113.5,198.51.100.0/24` и выполните `systemctl restart vkturn-api`.
  С других адресов админские запросы получат 403 даже с верным токеном.
  Приложение-админка на телефоне при этом перестанет подключаться, у неё меняется IP.
- Не публикуйте `config.txt`, `api.env`, архивы бэкапа и скриншоты с токеном.
- Если токен утёк, смените его скриптом: `sudo bash rotate-token.sh` (файл лежит рядом с
  `backup.sh`). Он сам заменит `ADMIN_TOKEN` и в `api.env`, и в `config.txt`, перезапустит
  `vkturn-api`, проверит, что новый токен принят, а старый нет, и выведет новый токен.
  Свой токен можно задать аргументом: `sudo bash rotate-token.sh НОВЫЙ_ТОКЕН` (буквы и цифры,
  от 24 символов). После этого обновите токен в боте и в приложении.
  Менять токен вручную в одном файле нельзя: при переезде `restore.sh` берёт токен из
  `config.txt`, и старый вернулся бы.

## 12. Привязка к устройству и смена подписи приложения

При первой активации ключ привязывается к телефону. Приложение отправляет на сервер не сам
`ANDROID_ID`, а хэш `SHA-256(ANDROID_ID + имя пакета)` (первые 32 символа).

| Что произошло | Привязка |
|---|---|
| Покупатель переустановил приложение (подпись та же) | сохраняется, ключ работает |
| Покупатель сбросил телефон до заводских настроек | теряется: у телефона новый `ANDROID_ID`, нужен `unbind` |
| Покупатель сменил телефон | нужен `unbind` (раздел 10) |
| Сменилась подпись приложения (debug → release, другой keystore) | теряется, см. ниже |

**Почему подпись влияет.** На Android 8 и новее `ANDROID_ID` зависит от ключа, которым подписано
приложение. Если тот же телефон получит сборку с другой подписью, `deviceId` станет другим,
и сервер ответит «Ключ уже активирован на другом устройстве».

**Ключ подписи release менять нельзя.** Android не обновит приложение, подписанное другим ключом,
а у всех покупателей одновременно слетит привязка. Файл `vkturn-release.jks` и пароли храните отдельно
от проекта и держите копию.

**Ранние тестеры (сборка `v1.0.0-user-only`, подписана debug-ключом).** Release-сборку Android не поставит
поверх debug: подписи разные, приложение придётся удалить (вместе с ним пропадут сохранённые
серверы и ключ). После установки `deviceId` будет новым. Рекомендуемый порядок, он не упирается
в лимит `unbind` (раз в 7 дней на ключ):

1. Выдайте тестеру новый тестовый ключ (`create` с новым `external_id`).
2. Тестер удаляет старое приложение и ставит release-сборку.
3. Тестер вставляет новую ссылку.
4. Старый тестовый ключ отзовите (`revoke`) или оставьте дожить до конца срока.

Если нужно сохранить старый ключ, сделайте для него `unbind` после переустановки. Если `unbind` для
этого ключа уже был за последние 7 дней, сервер ответит 429. Тогда выдайте новый ключ.

*Порядок для тестеров — рекомендация; окончательное решение за владельцем.*
