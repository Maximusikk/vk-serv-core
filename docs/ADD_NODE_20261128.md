# Добавление ноды: вскрытые проблемы и фиксы (2026-11-28)

Контекст: подключение второй ноды (NVHCloud, Франция) к мастер-серверу выявило цепочку
проблем «выдать токен → токен не работает → нода без ключей». Ниже — всё, что было
сломано, и что исправлено.

## Сервер (api)

1. **Нода, добавленная после создания подписок, навсегда оставалась без ключей.**
   `dispatchSubscription` помечает ноды только при СОЗДАНИИ подписки, а досыл
   (resendTick) ходит лишь по существующим строкам `subscription_servers`.
   **Фикс (3.9):** `handleMasterJoin` помечает все активные подписки `pending`
   для новой ноды — resendTick (30 с) сам создаёт ключи (срок — из активной
   доставки, лимит — из подписки). Тест: `TestMasterJoinBackfillsSubscriptions`.
2. **join-токены в памяти мастера** — рестарт API убивает выданные токены
   (403 на join). Приложение теперь выпускает токен прямо перед установкой,
   окно минимально. Будущий фикс: персистентность в БД.
3. **Устаревший бинарник на мастере** — призыв периодически запускать
   `upgrade.sh`; свежие фичи (поле `m` в bundle) появляются только с новым
   бинарником.

## Приложение (админка)

4. **Админка не могла выпустить join-токен**: `/master/join-tokens` принимает
   только `X-Master-Token` (2.4: админ-токену продавца выпускать нельзя), а
   приложение слало `X-Admin-Token`. Фикс: хранение `masterToken` (шифруется),
   парсинг `VKTURN_MASTER_TOKEN=` / `MASTER_TOKEN` из вывода install.sh и
   `config.txt` при SSH-настройке, запросы к реестру нод с `X-Master-Token`.
5. **Ручная команда «Добавить ноду» была нерабочей**: не скачивала install.sh
   (на свежем VPS его нет) и подставляла заглушку в `JOIN_PIN`. Фикс: полная
   автонастройка ноды по SSH (NodeSetupDialog): SSH → проверка → скачивание
   install.sh → установка `ROLE=node` c `JOIN_URL/JOIN_TOKEN/JOIN_PIN` →
   регистрация на мастере, с разбором ошибок (протухший токен, кривой пин).

## Эксплуатация (не код, но критично)

6. **TSPU/маршрут RU ↔ хостер**: TLS на нестандартные порты периодически
   «чернеет» (TCP проходит, данные тонут в обе стороны; TLS :443 без SNI —
   активный RST). Решение: релей API ноды через мастера:
   `DNAT master:7443 → node:7000` + **обязательный MASQUERADE** (без него
   обратный путь асимметричный и не работает; fwd-правила для ufw), юнит
   `vkturn-relay-france.service`; в реестре api ноды = `master:7443`.
   Активация/bundle идут через мастера (надёжно), data-plane (vkserv 56000,
   hy2 10443, пользовательские порты) — напрямую на ноду.
7. **Старые install.sh на нодах** не пишут `MASTER_TOKEN` в config.txt и не
   умеют join — всегда ставить скриптом зафиксированного коммита.
8. **Бэкап мастера** перед любыми операциями: backup.sh + копия базы
   (`sqlite3 .backup`), config.txt, api.env, юнита, старого бинарника.
