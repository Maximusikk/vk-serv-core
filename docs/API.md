# VKTurn API

Здесь описано, как управлять ключами по HTTP. Описание сверено с кодом сервера (`api/*.go`).

## Общее

**Адрес.** `http://<IP сервера>:<порт>`. Порт по умолчанию 7000 (флаг `-port`).
Любой путь работает и с префиксом `/v1`, и без него (`/v1/activate` = `/activate`).
В новых программах используйте `/v1`.

**Формат.** Тело запроса и ответ — JSON. Ошибка приходит так: `{"error": "текст"}`
и код HTTP. У `/activate` в ошибке есть ещё поле `code` (см. ниже).
Если метод неверный, приходит `405` с обычным текстом, не JSON.

**Тело запроса** — не больше 16 КБ. Битый JSON или слишком большое тело — `400`.

**Авторизация админских запросов.** Все пути `/admin/*` требуют заголовок
`X-Admin-Token: <токен>`. Токен лежит в `/opt/vkturn/config.txt`.

| Код | Когда |
|---|---|
| 401 | токен не тот |
| 403 | включён `-admin-allow`, и ваш IP не в списке (проверяется раньше токена) |
| 429 | больше 10 неверных токенов в минуту с одного IP; заголовок `Retry-After: 60` |

**Лимиты.** `/activate` — 10 запросов в минуту с одного IP (меняется флагом `-activate-rate`).
Лишние запросы получают `429`.

## Ключ

Формат: `xxxx-xxxx-xxxx-xxxx` (16 символов 0-9 a-f, четыре группы). Сервер хранит
строчными буквами. В запросах регистр не важен.

### Статус ключа

| Статус | Что значит |
|---|---|
| `pending` | ключ ни разу не активировали |
| `active` | порт выдан, срок не вышел, трафик не кончился |
| `expired` | срок вышел, или трафик кончился, или ключ активировали, но порт погашен |
| `revoked` | отозван (`/revoke`) |

В ответах поля `status` у ключа нет. Статус видно по полям: `revoked_at` не `null` — отозван;
`activated_at` равно `null` — `pending`; `active: true` — `active`; иначе `expired`.
Для фильтра списка параметр `status` есть (см. `GET /admin/keys`).

### Как считается срок

Срок задаёт поле `start` при создании ключа.

- `on_activation` (по умолчанию): срок идёт с первой активации в приложении.
  При создании сервер запоминает `duration_days` и ставит `expires_at = 0`.
  В момент первой удачной активации `expires_at = сейчас + duration_days * 86400`.
  Если активация не удалась (сервер заполнен, ошибка запуска), дни не тратятся.
- `on_create`: срок идёт с момента создания. `expires_at` проставляется сразу.

Повторная активация срок не сдвигает.

У ключа, который ещё не активирован, `expires_at = 0`, а `days_left` равен купленному сроку.
Это не бессрочный ключ. Отличить: у бессрочного `days_left = -1`.
После активации `duration_days` в ответе остаётся прежним, смотреть нужно на `expires_at`.

## Админские запросы

### POST /admin/keys/create — создать ключ

| Поле | Тип | Обязательно | Что значит |
|---|---|---|---|
| `expires_days` | число | да, если нет `unlimited` | Срок в днях, от 1 до 3650. `0` не принимается |
| `unlimited` | true/false | нет | `true` — бессрочный ключ. Тогда `expires_days` не нужен |
| `bytes_limit` | число | нет | Лимит трафика в байтах. `0` или не указан — без лимита. Не меньше 0 |
| `notes` | строка | нет | Заметка, до 200 символов |
| `external_id` | строка | нет | Номер заказа. Защита от дублей, см. ниже |
| `start` | строка | нет | `on_activation` (по умолчанию) или `on_create` |

Пример:

```json
{"expires_days": 30, "bytes_limit": 53687091200, "notes": "Иван", "external_id": "order-777"}
```

Ответ `200`:

| Поле | Что значит |
|---|---|
| `key` | ключ |
| `expires_at` | unix-время конца срока. `0` — бессрочный, либо срок ещё не пошёл (смотрите `duration_days`) |
| `duration_days` | сколько дней дадут с активации. `0`, если срок не ждёт активации |
| `start` | `on_activation` или `on_create`. У бессрочного ключа поля нет |
| `link` | готовая ссылка для приложения: `vkturn://key/<адрес>/<ключ>` |
| `duplicate` | `true`, если ключ с таким `external_id` уже был |

**external_id.** Если ключ с таким `external_id` уже есть, второй не создаётся: приходит
тот же ключ и `duplicate: true`. Остальные поля запроса при этом не сравниваются и не
применяются. Так повторный запрос от платёжки не плодит ключи.

**Адрес в `link`** берётся из флага `-public-url` (или переменной `PUBLIC_URL`). Если не задан,
в ссылке будет `127.0.0.1:7000`, и она не заработает. Задайте на сервере.

Ошибки `400`: `expires_days` меньше 0 или больше 3650; `expires_days` равен 0 без `unlimited`;
`bytes_limit` меньше 0; `notes` длиннее 200 символов; `start` не из двух разрешённых.

### GET /admin/keys — список ключей

Параметры (все необязательные):

| Параметр | Что значит |
|---|---|
| `external_id` | только ключи с этим номером заказа (точное совпадение) |
| `status` | `pending`, `active`, `expired` или `revoked` |
| `limit` | сколько вернуть, от 1 до 1000. Если не указан — все |
| `offset` | сколько пропустить с начала |

Ответ: массив объектов. Сначала новые. Если ничего нет — `[]`.

Поля объекта (те же, что у `GET /admin/keys/{id}`):

| Поле | Что значит |
|---|---|
| `id` | ключ |
| `created_at` | когда создан (unix) |
| `activated_at` | когда активирован (unix) или `null` |
| `expires_at` | конец срока (unix). `0` — бессрочный или срок ещё не пошёл |
| `duration_days` | срок в днях, который начнётся с активации (см. выше) |
| `days_left` | сколько дней осталось (целых). `-1` — бессрочный. `0` — срок вышел. До активации — весь срок |
| `bytes_used` | израсходовано байт |
| `bytes_limit` | лимит в байтах, `0` — без лимита |
| `port` | выданный порт или `null` |
| `notes` | заметка |
| `active` | `true`, если ключ сейчас работает |
| `device_bound` | `true`, если ключ привязан к устройству |
| `revoked_at` | когда отозван (unix) или `null` |

### GET /admin/keys/{id} — один ключ

Те же поля. `404`, если ключа нет.

### PATCH /admin/keys/{id} — изменить ключ

Передавайте только то, что меняете.

| Поле | Что делает |
|---|---|
| `expires_days` | Продлевает на столько дней (подробности ниже). `0` — сделать бессрочным. До 3650, не меньше 0 |
| `bytes_limit` | Ставит новый лимит в байтах (не добавляет). `0` — без лимита |
| `notes` | Меняет заметку, до 200 символов |

Как работает `expires_days`:

- Ключ уже активирован: срок продлевается от конца текущего срока. Если срок уже вышел, то от сегодняшнего дня.
- Ключ ещё не активирован (срок с активации): дни добавляются к `duration_days`, отсчёт не
  запускается. Общий срок не больше 3650 дней, иначе `400`.
- `expires_days: 0` у любого ключа делает его бессрочным.

**Осторожно с бессрочными ключами.** Если у бессрочного ключа передать `expires_days: 30`,
сервер поставит срок 30 дней от сегодня, и ключ перестанет быть бессрочным. Перед продлением
проверяйте, что `days_left` не равен `-1`.

Ответ `200`: `status` (`"updated"`), `expires_at`, `duration_days`, `bytes_limit`, `notes`
и `new_port`, если порт подняли заново.

**Новый порт.** Если ключ был активирован, но порт погашен (вышел срок или кончился трафик),
а вы продлили срок или подняли лимит, сервер сам выдаёт новый порт и возвращает его в `new_port`.
Пользователю ничего вводить не надо, приложение переподключится само.
Отозванный ключ продлением не поднимается.

Ошибки: `400` (отрицательные числа, больше 3650, длинная заметка), `404` (нет ключа).

### POST /admin/keys/{id}/add_traffic — докупить трафик

```json
{"bytes": 10737418240}
```

`bytes` — сколько байт прибавить к лимиту, больше 0. 10 ГБ = 10737418240.

Ответ `200`: `{"status": "updated", "bytes_added": ...}` и `new_port`, если погашенный
порт подняли заново.

Ошибки: `400` — `bytes` не больше 0, либо у ключа нет лимита (`bytes_limit = 0`),
докупать нечего; `404` — нет ключа.

### POST /admin/keys/{id}/unbind — снять привязку к устройству

Нужен, когда покупатель сменил телефон. Тело не нужно.

Сервер сбрасывает привязку, меняет пароль порта и токен. Старые конфиги перестают работать.
Покупатель вставляет ту же ссылку-ключ в приложении на новом устройстве.

Не чаще, чем раз в 7 дней на один ключ (флаг `-unbind-days`, `0` — без ограничения).
Раньше срока — `429` и текст, через сколько часов можно повторить.

Ответ `200`: `{"status": "unbound", "key": "..."}`. `404` — нет ключа.

### POST /admin/keys/{id}/revoke — отозвать ключ

Для возврата денег или блокировки. Порт гасится, `/activate` и `/status` отвечают отказом.
Запись остаётся в базе. Повторный вызов безвреден: время отзыва не меняется.

Ответ `200`: `{"status": "revoked", "key": "...", "revoked_at": <unix>}`. `404` — нет ключа.

Обратно отозванный ключ вернуть нельзя: продление и докупка его не поднимают.

### DELETE /admin/keys/{id} — удалить ключ насовсем

Порт гасится, запись стирается. История продаж пропадает. Для обычного отзыва
используйте `revoke`.

Ответ `200`: `{"status": "deleted", "key": "..."}`. `404` — нет ключа.

### GET /admin/stats — сводка

| Поле | Что значит |
|---|---|
| `total_keys` | всего ключей |
| `active_keys` | сколько работает сейчас |
| `total_bytes_used` | трафик по всем ключам, байт |
| `used_ports` | занято портов |
| `free_ports` | свободно портов в диапазоне |
| `capacity` | сколько ключей сервер потянет: `-max-active`, а если не задан — весь диапазон портов |
| `active_units` | сколько процессов `vkserv@` запущено |

### GET /admin/health — состояние сервера

| Поле | Что значит |
|---|---|
| `ok` | `false`, если ссылка VK не проходит проверку или на диске меньше 100 МБ |
| `vk_link_ok` | ссылка VK в порядке |
| `vk_link_error` | что не так со ссылкой (есть только при ошибке) |
| `disk_free_mb` | свободно места на диске, МБ |
| `active_vkserv` | сколько `vkserv@` запущено |
| `api_version` | версия API |
| `uptime_sec` | сколько секунд работает API |

### PUT /admin/vk — сменить ссылку VK

```json
{"vk_link": "https://vk.com/call/join/abcDEF123"}
```

Ссылка должна подходить под `https://vk.com/call/join/...` или `https://vk.ru/call/join/...`
(буквы, цифры, `_`, `-`). Иначе `400`. Новая ссылка применяется ко всем новым активациям.
Уже выданные конфиги она не меняет.

## Запросы пользователя (без админского токена)

### POST /activate — активировать ключ

| Поле | Обязательно | Что значит |
|---|---|---|
| `key` | да | ключ, регистр не важен |
| `device_id` | да | идентификатор устройства, до 128 символов |
| `vk_link` | нет | запасная ссылка VK, нужна только старым серверам без ссылки в настройках |

Первое устройство, которое активировало ключ, привязывается к нему. Повторная активация
с того же устройства возвращает тот же конфиг и срок не двигает.

Ответ `200`: `token` (для `/status`), `config` (настройки подключения), `expires_at`, `bytes_limit`.

Ошибки (поле `code` добавлено, текст сообщения для пользователя):

| Код HTTP | `code` | Причина |
|---|---|---|
| 400 | нет | нет `key`, или нет `device_id` (старое приложение) |
| 404 | `key_not_found` | такого ключа нет |
| 403 | `revoked` | ключ отозван |
| 403 | `expired` | вышел срок |
| 403 | `limit_exhausted` | кончился трафик |
| 403 | `bound_other_device` | ключ привязан к другому устройству |
| 503 | нет | сервер заполнен (`-max-active`), либо в настройках нет ссылки VK |
| 429 | нет | больше 10 запросов в минуту с этого IP |

### GET /status — состояние подписки

Заголовок: `Authorization: Bearer <token>` (токен из ответа `/activate`).

Ответ `200`: `active`, `expires_at` (`0` — бессрочный), `days_left` (`-1` — бессрочный),
`bytes_used`, `bytes_limit` (`0` — без лимита), `revoked`.

Ошибки: `401` — нет заголовка, `404` — токен не найден (например, после `unbind`).

### GET /health

Без токена. Ответ: `{"ok": true}`.

## Настройки API (флаги и переменные)

Задаются в `/opt/vkturn/api.env` (переменные) или в unit-файле `vkturn-api` (флаги).
После правки: `systemctl restart vkturn-api`.

| Флаг | Переменная | По умолчанию | Что делает |
|---|---|---|---|
| `-bind` | | `127.0.0.1` | на каком адресе слушать (`0.0.0.0` — на всех) |
| `-port` | | `7000` | порт API |
| `-admin-token` | `ADMIN_TOKEN` | | токен для `/admin/*` |
| `-public-url` | `PUBLIC_URL` | | адрес для ссылок в ответе `create`, например `203.0.113.10:7000` |
| `-admin-allow` | `ADMIN_ALLOW` | пусто (с любого IP) | список IP или сетей через запятую, с которых можно `/admin/*` |
| `-max-active` | `MAX_ACTIVE` | 0 (без ограничения) | сколько ключей может быть активно одновременно |
| `-unbind-days` | `UNBIND_DAYS` | 7 | как часто можно делать `unbind` одному ключу |
| `-activate-rate` | | 10 | запросов `/activate` в минуту с одного IP |
| `-port-start`, `-port-end` | | | диапазон портов для ключей |
| `-db` | | `/opt/vkturn/api.db` | путь к базе |

`-admin-allow` смотрит только на адрес, с которого пришло соединение. Заголовок
`X-Forwarded-For` не учитывается. Если включить, приложение-админка на телефоне
(у неё меняется IP) перестанет работать.

## Примеры

```bash
H="X-Admin-Token: $ADMIN_TOKEN"
API=http://203.0.113.10:7000/v1

# Выдать ключ на 30 дней, 50 ГБ, по номеру заказа
curl -s -X POST $API/admin/keys/create -H "$H" \
  -d '{"expires_days":30,"bytes_limit":53687091200,"external_id":"order-777"}'

# Бессрочный ключ
curl -s -X POST $API/admin/keys/create -H "$H" -d '{"unlimited":true}'

# Найти ключ по заказу
curl -s "$API/admin/keys?external_id=order-777" -H "$H"

# Продлить на 30 дней
curl -s -X PATCH $API/admin/keys/d454-098a-1234-abcd -H "$H" -d '{"expires_days":30}'

# Докупить 10 ГБ
curl -s -X POST $API/admin/keys/d454-098a-1234-abcd/add_traffic -H "$H" -d '{"bytes":10737418240}'

# Сменил телефон
curl -s -X POST $API/admin/keys/d454-098a-1234-abcd/unbind -H "$H"

# Возврат денег
curl -s -X POST $API/admin/keys/d454-098a-1234-abcd/revoke -H "$H"
```

## Порядок для бота продавца

1. Оплата прошла. Вызвать `create` с `external_id` = номер заказа. Отправить покупателю `link`.
   Если платёжка прислала уведомление дважды, второй вызов вернёт тот же ключ (`duplicate: true`).
2. Продление. Сначала `GET /admin/keys/{id}`: если `days_left = -1`, продлевать нельзя (см. выше).
   Иначе `PATCH` с `expires_days`.
3. Докупка трафика: `add_traffic`. Если у ключа нет лимита, придёт `400`.
4. Смена телефона: `unbind`, затем покупатель вставляет ту же ссылку на новом устройстве.
5. Возврат денег: `revoke`.

Готовый пример бота: `examples/seller_bot/`.
